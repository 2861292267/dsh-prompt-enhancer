# 独有功能

本插件与同类插件的差异点。不是"功能更多"，而是**两个方向上的做法不同**。

---

## 一、多风格对比（`⇄`）

### 为什么做

单次改写是"接受或拒绝一个答案"——用户看不到别的可能，只能凭感觉判断好坏。
把**同一份草稿**同时跑多个风格，选择从"看不见"变成"看得见"。

同类插件（如 Fishsb/dsh-prompt-enhancer）的做法是**模型链**：按序尝试多个模型，
第一个成功即止。那是**容错**（找一个能用的），不是**比较**（看哪个更好）。
方向不同，本插件的做法是**一次给多个方案**。

### 怎么用

输入草稿 → 点 `⇄` → 面板逐个填入结果 → 看中哪个点「用这个」。

### 关键设计

| 决策 | 为什么 |
|---|---|
| **部分成功是常态** | 某个风格限流失败，不能把其它三个好结果一起丢掉。返回的是**逐风格结果**而非整批成败 |
| **NDJSON 流式** | 快的风格先显示，不必等最慢的那个。四个风格串行时，一次性返回会让体感慢四倍 |
| **串行而非并行** | 共用同一个 provider 与凭据，并发调用容易触发限流，且部分失败更难归因 |
| **上限 4 个** | 每个风格是一次完整模型调用，同时约束延迟与花费。4 个刚好覆盖全部内置风格 |
| **去重** | 同一风格跑两次是浪费一次调用，且产生两条无法区分的条目 |
| **采纳走同一条写入路径** | 「用这个」复用主按钮的 `writeDraft` + `backup`，所以**自动获得撤销与防覆盖守卫**，不需要为它单独实现一套 |

### 接口

```
POST /plugins/dsh-prompt-forge/compare
{ "draft": "...", "styles": ["default", "concise"] }

→ 每行一个 JSON（NDJSON）：
{"style":"default","ok":true,"prompt":"..."}
{"style":"concise","ok":false,"error":"额度耗尽"}
```

## 二、自定义风格模板（`styles` 配置）

### 为什么做

内置风格写死在代码里，用户无法增改。同类插件的模式也是硬编码的固定几种。

改为**数据驱动**：风格就是一段附加在 WorkBuddy 指令后的文本，
所以新增一个风格是**配置**，不是**改代码**。

### 怎么用

在插件配置里加 `styles`：

```yaml
- id: prompt-enhancer
  config:
    styles:
      prd: |
        按我们的 PRD 模板组织：背景 / 目标 / 非目标 / 验收标准。
        术语保持英文原样，不要翻译。
      sql: |
        改写为一段明确的 SQL 需求：说明表、字段、过滤条件与预期结果。
```

重启后下拉里就多出这些风格，`/enhance --prd <草稿>` 也能直接用。

### 关键设计

| 决策 | 为什么 |
|---|---|
| **不得覆盖内置** | 尤其 `default` 必须保持与 WorkBuddy **逐字节相同**。自定义条目若与内置同名直接跳过 |
| **非法条目静默跳过** | id 不合法、文本为空、类型不对——一律忽略而非报错。配置写错不该让功能失效 |
| **id 形状受限** | `^[a-z][a-z0-9_-]{0,31}$`。既防注入到 URL / `<option>`，也避免与内置撞名 |
| **数量上限 12** | 失控的配置不该撑爆每次请求 |
| **配置时合并一次** | `/status`、路由、斜杠命令读**同一张解析后的表**。改动前这三处各读各的，可能互相不一致 |
| **`defaultStyle` 可指向自定义** | 但未知值仍回落 `default`，不会把空指令发给模型 |

## 三、与同类插件的差异一览

| 维度 | Fishsb/dsh-prompt-enhancer | 本插件 |
|---|---|---|
| 风格 | 硬编码 5 种模式 | **内置 4 种 + 用户可自定义** |
| 多模型 | 模型链（按序重试，取第一个成功） | **多风格并排对比（一次给多个方案）** |
| 语音 | 有 | 无（不在本项目范围） |
| 服务重启 | 有 | 无（交回官方 plugin manager） |
| 许可 | 无 LICENSE | MIT |
| 架构 | CJS + 构建产物（单文件 314 KB） | 原生 ESM，无构建步骤（全部 ~90 KB） |

**不做语音的理由**：那是另一个产品级能力，依赖官方 `speechToText` 与 VAD、
快捷键、音频处理，做进来会让本插件从"输入框旁一个按钮"膨胀成需要独立设置页的东西。
聚焦比堆功能更难，也更值钱。

## 四、验证

```powershell
cd <插件目录>
npm test
```

多风格对比的测试集中在**部分失败**、**取消**、**去重**、**上限**四类边界——
这些才是这个功能真正容易出错的地方。
