# 独有功能

本插件与同类插件的差异点。

> 设计参考了同生态里的成熟实现（尤其是设置面板的挂载契约与配置持久化策略），
> 但代码是独立编写的：那个项目用 CJS + 构建产物，本项目是原生 ESM、无构建步骤。

---

## 一、自定义风格模板

### 为什么做

内置风格写死在代码里，用户无法增改；同类插件的模式也是硬编码的固定几种。

改为**数据驱动**：风格就是一段附加在 WorkBuddy 指令后的文本，
所以新增一个风格是**配置**，不是**改代码**。

### 怎么用

两种方式，任选：

**A. 设置面板（推荐）** —— 设置 → 提示词锻造 → 自定义风格，每行一条：

```
prd | 按我们的 PRD 模板组织：背景 / 目标 / 非目标 / 验收标准。
sql | 改写为一段明确的 SQL 需求：说明表、字段、过滤条件与预期结果。
```

**B. 配置文件** —— `~/.dsh/dsh-prompt-forge.config.json`：

```json
{
  "styles": {
    "prd": "按我们的 PRD 模板组织：背景 / 目标 / 非目标 / 验收标准。"
  }
}
```

保存后重启 DSH，下拉里就多出这些风格，`/enhance --prd <草稿>` 也能用。

### 关键设计

| 决策 | 为什么 |
|---|---|
| **不得覆盖内置** | 尤其 `default` 必须与 WorkBuddy **逐字节相同**。自定义条目与内置同名直接跳过 |
| **非法条目静默跳过** | id 不合法、文本为空、类型不对——忽略而非报错。配置写错不该让功能失效 |
| **id 形状受限** | `^[a-z][a-z0-9_-]{0,31}$`。防注入到 URL / `<option>`，也避免与内置撞名 |
| **数量上限 12** | 失控的配置不该撑爆每次请求 |
| **配置时合并一次** | `/status`、路由、斜杠命令、设置面板读**同一张解析后的表**，不会互相不一致 |
| **`defaultStyle` 可指向自定义** | 但未知值仍回落 `default`，不会把空指令发给模型 |

## 二、设置面板

### 挂载契约

DSH 设置对话框的左侧导航来自槽位 `settings.section`。注册方式：

```js
ctx.slots.inject('settings.section', () => ctx.slots.register(
  {
    name: 'settings.section',
    id: 'prompt-forge',
    order: 50,
    label: () => '提示词锻造',   // 导航文字
    locale: 'dsh-prompt-forge',  // 可选，接 i18n
  },
  SettingsPanel,
))
```

宿主按 `order` 升序排列（读自宿主 `dsh-client-ui-settings-general` 的
`ctx.slots.entries('settings.section')`）。

### 面板提供什么

| 区块 | 内容 |
|---|---|
| **当前配置** | 模型服务 / 模型 / 默认风格 / 内置风格 —— 只读展示实际生效值 |
| **自定义风格** | 可编辑的文本域（`名称 \| 指令`），保存写回磁盘 |
| **配置文件路径** | 显示配置落在哪里，便于手工排查 |

**`provider` / `model` 故意只读**：它们由 profile 的 patch 文件决定。
让一个设置表单能改这两项，等于给"某次误操作把改写全部指向另一个模型"开了口子，
收益为零。

面板读取失败时显示明确的"不可用"状态，而不是一个空表单——
宿主服务挂掉不该看起来像"所有配置都没设置"。

### 配置持久化

存在 `~/.dsh/dsh-prompt-forge.config.json`，**不是 localStorage**。

原因是同类实现踩过的坑值得照学：**DSH Desktop 每次启动动态分配端口**
（`listen(0)`），而 Chromium 按 Origin（协议://域名:端口）隔离 localStorage ——
端口一变，存储就是空的，用户配置看起来"丢了"。
磁盘文件跨端口共享，没有这个问题。

写入策略：

| 做法 | 理由 |
|---|---|
| **顶层键 merge**，非整体替换 | 将来多写入方不互相清空 |
| **原子替换**（写临时文件 + rename） | 中途崩溃不会留下半个 JSON |
| **读取永不抛错** | 文件损坏 / 只读 / 被截断 → 退回默认值，而不是让插件起不来 |
| **优先级：用户配置 > 静态 config** | 面板里改过的值盖住 patch 文件里的初始值，符合直觉 |
| **只写白名单键** | `defaultStyle` / `slashCommand` / `styles`。其余键即使发过来也忽略 |

## 三、不做的事（及理由）

| 不做的 | 理由 |
|---|---|
| **语音识别** | 那是产品级能力（VAD、快捷键、音频处理、独立设置页），做进来会让本插件从"输入框旁一个按钮"膨胀成另一个东西。聚焦比堆功能更难 |
| **模型链**（按序重试多个模型） | 宿主的模型池已经处理可用性；插件再包一层只会让失败更难归因 |
| **服务重启** | 交回官方 plugin manager。插件自建重启路径要重复实现它的全部守卫 |
| **多风格并排对比** | **做过后按用户要求移除** —— 实际使用中价值不足，且每次要跑多个模型调用 |

## 四、验证

```powershell
cd <插件目录>
npm test
```

重点覆盖的边界：

- `config-store.mjs` —— 配置损坏 / 缺失 / 超大 / merge 语义 / 原子性
- `custom-styles.mjs` —— 不得覆盖内置 / 非法条目跳过 / 上限
- `revert-scope.mjs` —— 撤销的作用域（含反向验证）
- `f1-guard.mjs` —— 防覆盖护栏的时序（含反向验证）
